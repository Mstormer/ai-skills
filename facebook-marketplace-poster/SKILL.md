# Facebook Marketplace Poster

Create or publish one prepared inventory item through Facebook Marketplace using the user's signed-in browser session and source files.

## Start by coaching the user

If the user has not supplied an item folder, ask them to choose or provide the folder containing the listing details and photos. Do not guess a default path.

After receiving the folder, inspect it and coach the user through anything needed to finish the listing. Ask concise, targeted questions for missing or ambiguous details such as title, price, category, condition, description, location, pickup or delivery method, public-meetup preference, and desired groups. Explain what each choice affects when useful. Do not open Facebook or publish until required details are resolved.

## Inputs

- Item folder selected or supplied by the user.
- One Markdown listing file in that folder. Prefer `Marketplace Listing.md`; otherwise use the only non-sample Markdown file.
- JPEG photos in the same folder.
- Optional Marketplace groups explicitly selected by the user or supplied as configuration.
- Optional tracking CSV explicitly identified by the user or supplied as configuration.

Never infer groups, location, delivery preferences, tracking files, or account-wide settings from unrelated prior tasks. If the user does not want groups, confirm that Marketplace-only placement is acceptable.

## Validate source files first

Before opening Facebook:

1. Resolve the item folder and read its listing Markdown.
2. Extract title, price, category, condition, description, location, delivery method, public-meetup preference, and photo filenames.
3. Confirm every referenced photo exists. Confirm every JPEG intended for this item is included. Stop and report any mismatch.
4. Treat source values as authoritative. Do not replace them with autogenerated copy or guessed item details.
5. Ask the user about any missing or ambiguous field before publishing.

Descriptions should sound like ordinary Marketplace sale posts: identify the item, visible condition, included items, and price-relevant facts. Do not add internal notes, seller instructions, or requests that buyers test, count, inspect, verify, or confirm anything at pickup.

## Browser workflow

Use Chrome or another available computer-use browser with the user's signed-in Facebook session.

1. Open `https://www.facebook.com/marketplace`.
2. Choose `Selling`, then `Create listing`.
3. Choose `Item for sale` when Facebook presents listing types.
4. Upload every source JPEG. Verify thumbnails and photo count.
5. Fill title, price, category, condition, and description from the listing file. Replace any AI-generated description.
6. Choose the closest accurate Facebook category. Do not silently substitute a misleading category.
7. Set city/state from the source location using the matching official suggestion.
8. Select `Local pickup` when specified and enable `Public meetup` when specified. Do not alter account-wide defaults unless asked.
9. Keep the Marketplace public listing enabled. Select only explicitly requested or configured groups.
10. Before publishing, compare the preview with the source: photos, title, price, category, condition, description, location, delivery, meetup, and groups.
11. Click `Publish` only when the user explicitly asked to publish and the review passes.
12. Verify a success state or listing confirmation. If confirmation is absent, report incomplete status and do not claim success.

## Group safety

Never select a group merely because it appeared in a previous task. If a group is restricted to a niche audience, select it only when the source text or verified item evidence clearly qualifies the item. Otherwise ask the user or leave it unselected.

## After confirmed publication

Only after Facebook confirms publication, perform configured bookkeeping:

- Rename the source folder only when the user or configuration requests it. Use a non-colliding destination; never overwrite an existing folder.
- Update the configured tracking CSV only when requested. Match by source photo filename first, then exact title. Add a status column if needed while preserving existing rows and columns.
- Set the matching status to `POSTED` and update stored photo paths if the folder was renamed.
- Verify the renamed folder, photos, unique CSV match, and persisted status.

If a destination folder already exists, the CSV match is not unique, or the tracking configuration is unclear, stop and report instead of guessing.

## Common UI traps

- Facebook may insert AI-generated text after upload; replace it with source description.
- Category suggestions may be wrong; choose an accurate category or pause for user input.
- Group lists can change; verify every selected group during the current session.
- A disabled Publish button may indicate upload processing or required fields. Inspect validation messages and fix only source-backed fields.
- Never paste passwords, payment details, or other sensitive information into a listing.

## Completion report

Report item title, price, photo count, selected placements, Facebook confirmation, and any folder or tracking update. Clearly identify anything requiring user input or remaining unresolved.
