# Cross-posting to OfferUp, Craigslist and Mercari

Optional. Offer it in the outline (step 4b); do it only for sites the user picks, after the Facebook listing is approved (and normally after it's posted).

## Before starting

- Use the user's own signed-in sessions in Chrome (background tab, human pace). Never create an account, sign in with a password, or verify a phone number for the user: if they're not signed in, ask them to sign in in that tab, then carry on.
- Check availability in the user's country: these are mainly US sites (Craigslist covers many cities worldwide). Offer local equivalents where they apply (e.g. Gumtree, Kijiji, Vinted, Kleinanzeigen, Leboncoin, Trade Me) on the same terms.
- **Fees cost money:** Mercari charges a selling fee on sales; Craigslist charges posting fees in some categories and cities; any site may offer paid promotion. State any fee the site shows before posting, and never pay for posting or promotion without the user confirming the item and amount.

## Per site

Show a short outline of what each site will get (it's the Facebook listing adapted to the site's fields):

| Site | Notes |
|---|---|
| OfferUp | Local pickup or shipping; title, price, category, condition, description, photos. |
| Craigslist | Choose the user's city site and the correct "for sale" category; enter a general location (cross streets or area), never a full address; show the email privacy option the user wants (Craigslist relay recommended). |
| Mercari | Shipping-based: needs weight/size and who pays shipping; price research should include shipping cost. Ask before using shipping if the user only wants local pickup. |

Then:
1. Fill only approved values; adapt categories honestly (pause if no category fits).
2. Review the preview against the outline, publish only with the user's explicit yes, and verify the site confirms the post.
3. Record each cross-post (site, URL, date, price) in the item's posting history.

## Keep them in sync

When the item sells, the price drops or a listing is removed, update or close the cross-posts too (`after-posting.md`) and record it. If a cross-post can't be updated, tell the user so it isn't left live after the item is gone.
